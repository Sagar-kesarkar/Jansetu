## 1. A functioning end-to-end flow for the track's core use case

| Step | Implementation |
|---|---|
| Citizen submits voice or text in an Indian language | `POST /intake/voice`, `POST /intake/text`, `POST /intake/whatsapp` — `backend/app/routers/intake.py` |
| Audio → text | `backend/app/services/speech.py` (Gemini native audio) |
| Unstructured text → category, urgency, location, English summary | `backend/app/services/gemini.py::extract_request` |
| Free-text place → district code | `backend/app/services/geocode.py::resolve_district` |
| Persist without PII | `backend/app/db/models.py::CitizenRequest` |
| Acknowledge in the citizen's language | `backend/app/services/pipeline.py::ingest` |
| Join with demographics + infra + investment | `backend/app/analytics/aggregate.py::build_cells` |
| Score unmet need | `backend/app/analytics/priority.py::score` |
| Hotspots | `GET /hotspots` — `backend/app/analytics/hotspots.py` |
| Ranked recommendations with evidence | `GET /recommendations` — `backend/app/analytics/explain.py` |

The whole path is exercised by `backend/tests/test_intake_e2e.py`, which asserts a
submitted message ends up influencing a ranked recommendation.

## 2. Mandatory integration of Google AI

Gemini 2.5 Flash via the official `google-genai` SDK, used in four distinct ways:

1. **Speech recognition** (multimodal audio input) — `services/speech.py`
2. **Structured extraction** with a constrained JSON response schema — `services/gemini.py::extract_request`
3. **Translation** into English for cross-language aggregation — `services/translate.py`
4. **Generative policy briefs** grounded in computed evidence — `services/gemini.py::write_policy_brief`

Live proof at `GET /capabilities`, which reports the model, the provider and the
list of tasks Gemini performs.

Design rule worth stating in the video: **the model narrates the evidence, it
never produces the numbers.** Scores come from `analytics/priority.py`, which is
pure Python and deterministic. That is why the ranking is auditable.

## 3. Real or realistic data

See [DATA_SOURCES.md](DATA_SOURCES.md) for full provenance. Summary:

- **Real** — 46 districts across 18 states with Census 2011 population and
  literacy figures (`data/reference/districts.csv`), plus 342 place aliases —
  localities, tehsils, native-script spellings, former names and PIN codes —
  in `data/reference/place_aliases.csv`.
- **Derived, deterministic** — infrastructure coverage indices and scheme
  allocations, generated by `data/scripts/build_reference.py` with a fixed seed.
- **Synthetic, deliberately biased** — 600 citizen requests in 8 languages,
  `data/scripts/generate_requests.py`. Volume scales with internet penetration,
  because that is the real-world reporting bias the platform corrects for.

Nothing is presented as official data that is not. Every generated column is
labelled in the script docstring and in DATA_SOURCES.md.

## 4. Built for India — scales across states, not one city

- The unit of analysis is the **district**, keyed to LGD codes, which is the
  join key every central scheme dashboard already uses. Add rows to
  `districts.csv` and the country is covered — no code changes.
- Normalisation happens **across the queried set**, so filtering to one state
  ranks its districts against their own peers rather than against Delhi.
  `analytics/priority.py::_minmax`.
- The sector taxonomy maps 1:1 to **national schemes** (Jal Jeevan Mission,
  PMGSY, Swachh Bharat, Ayushman Bharat, Samagra Shiksha, BharatNet, PMAY-G,
  PMKSY, RDSS) — `backend/app/models/taxonomy.py`. Recommendations arrive as
  budget lines an official can actually act on.
- Seed data spans 18 states and all 13 supported languages, chosen for
  aspirational-district variety *and* deliberate contrast: Nabarangpur and Pune
  are both in the set because the pitch is about the gap between them.

## 5. Multilingual and voice support

- **13 Indian Languages**: configured in `backend/app/i18n/languages.py` (Hindi, Bengali, Tamil,
  Telugu, Marathi, Gujarati, Kannada, Malayalam, Punjabi, Odia, Assamese, Urdu, English).
- **Voice on Every Channel**:
  - **Web recorder**: `POST /intake/voice` and `POST /intake/report` (multipart audio + photo).
  - **WhatsApp Cloud API**: `POST /intake/whatsapp` handles voice notes, photographs, and text with message deduplication (`backend/app/channels/whatsapp.py`).
  - **IVR Feature-Phone Line**: Provider-agnostic call-flow state machine (`backend/app/channels/state.py` and `ivr.py`) with pre-generated 8 kHz mono narrowband WAV prompts (`data/ivr_prompts/`), DTMF language selection, open-ended recording via Gemini multimodal audio, native-script confirmation, and digit-by-digit docket reference readback.
- **Provider-Agnostic Telephony & Zero-Cost Architecture**: Demonstrated honestly via HTTP simulator (`POST /ivr/simulate` and `backend/app/channels/simulator.py`) and standard webhook (`POST /ivr/webhook`) mapping to Twilio TwiML and Exotel without paid dependencies. See [TELEPHONY_ADAPTERS.md](TELEPHONY_ADAPTERS.md).
- **Native-Language Acknowledgements**: returned in the citizen's own script (Devanagari, Bangla, Tamil, etc.), never forced into English.
- **Seed Corpus**: 600 requests with authentic native-script sentences across 8 languages.
