The problem

The people who need the most ask the least.

  • Governments can't consolidate what citizens need. Feedback is scattered across WhatsApp, phone calls, paper, and portals — in 22+ official languages.
  • The feedback that does arrive is skewed: filing a complaint quietly assumes literacy, a smartphone, a portal, and the "right" language.
  • So the districts with the greatest unmet need file the fewest requests — and public investment ends up following the loudest, not the neediest.

Why now

The barrier is the channel — not apathy.

  • Hundreds of millions of Indians reach government by voice and feature phone, not web forms. A farmer in Nabarangpur sends a voice note in Odia — she doesn't fill in a portal.
  • AI can now transcribe, translate and understand that voice note as reliably as a typed form.
  • Remove the channel barrier and the silent districts finally show up in the data. That is the moment JanSetu is built for.

The solution

One platform, three surfaces.

Raw human voice in one end; prioritized, evidence-backed public-investment guidance out the other.

The AI approach

From a voice note to a structured record.

A single Gemini pipeline runs on every request — the original is always preserved beside the machine's reading of it.

1

Transcribe

Voice & IVR calls become text.

2

Translate

Any Indian language ↔ English.

3

Classify

Sector + urgency (1–5), with a confidence score.

4

Locate

Extract the place, match to the official LGD district code.

5

Triage

Flag spam / tests / non-requests — kept, never deleted.

6

Summarize

An English summary for officials.

Photos are analyzed for evidence, described in words, then the image is discarded — the description travels, the file does not.

Privacy & trust by design

A public good has to earn trust first.

  • No PII is stored — no name, phone number, address, IP or device is ever kept.
  • Reporters are a one-way cryptographic pseudonym: you can link a person's own reports, but you can never recover the person.
  • Location is never stored finer than ward level; photos are analyzed, then discarded.
  • Officials see honest state — replies are marked "queued," never falsely shown as "delivered."

Why it's deployable

Runs today, not someday.

Standards-based from day one

Every request keys to the government's own LGD district codes — interoperable with existing systems, no bespoke mapping.

Channels plug in, core stays put

WhatsApp, SMS and IVR arrive through adapters. Adding a channel doesn't touch the pipeline or the console.

No AI lock-in

Gemini today, any capable model tomorrow. The AI layer is a swappable boundary, not a dependency.

Light footprint

SQLite for a pilot → Postgres for a state, same code. Open and self-hostable — no proprietary piece a state can't run.

How it scales across India

From one block to seven hundred districts.

  • The data model is already national. Because every request keys to an LGD code, "one district" and "all of India" are the same query.
  • Language-agnostic. Adding a 12th — or 22nd — language is configuration, not a rewrite.
  • State-scoped consoles. Each administration sees its own queue by default; the analytics roll up to the centre automatically.
  • Federated by design. Pilot in one block, expand to a state, aggregate nationally — no re-architecture at any step.
